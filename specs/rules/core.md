# Core Rules

## Priority

1. User explicit instruction
2. Project safety and non-destructive changes
3. This ruleset (specs/rules/*)
4. Legacy docs

## Hard Constraints

- Never start execution before explicit user approval to proceed.
- Do not run destructive commands unless explicitly approved.
- Keep changes minimal and traceable.
- For ambiguous choices, present options with tradeoffs and a recommendation.

## Output Style

- Keep output concise and actionable.
- For complex tasks, always provide: decision, plan, execution status.
