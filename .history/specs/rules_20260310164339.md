# Agent 执行规则

> 本文件是 agent 的硬约束，每次任务开始前必须全量读取。
> 保持精简（≤500行），超过则拆分。

---

## 1. 规则自身管理

### 1.1 版本检查
- 每次任务开始前，读取本文件头部版本号
- 与 memory 中存储的版本比对，版本不同则全量重读并更新 memory 中的版本记录
- 版本相同则直接使用 memory 中缓存的规则要点

### 1.2 规则更新原则
- **最小修改**：只改变动的地方
- **引用联动**：所有引用该改动的地方都要同步修改（用 search_files grep 查找引用）
- **禁止顺手重构**：未改动的地方不要随意修改

## 2. 任务完成记录规则

### 2.1 Skill 记录（可复用操作步骤）
任务完成后，自动将执行步骤提炼为 skill：

**存储方式**：同时写入 memory MCP 和 `specs/skills/` 目录

**Skill 格式**：
```markdown
# Skill: {skill名称}
- 触发场景: {什么情况下可以复用}
- 步骤:
  1. xxx
  2. xxx
- 注意事项: xxx
- 关联文件: [路径列表]
```

**Skill 规则**：
- 提炼可复用的操作步骤，去掉项目特定细节，保留通用流程
- 记录触发场景和注意事项
- 如果与已有 skill 重复，合并更新而非新建
- memory 中用 entityType: "skill" 标记，方便语义搜索

### 2.2 决策日志（过程记录）
决策过程和问题记录写入 `process/task-log-{日期}-{摘要}.md`

**Task Log 格式**：
```markdown
# 任务: {任务名}
- 日期: {YYYY-MM-DD}
- 触发: {用户指令 / 自动触发}
- 目标: {目标描述}

## 执行过程
1. {步骤描述}

## 变更文件
- {文件路径}: {变更摘要}

## 决策记录
- {为什么选 A 不选 B}: {原因}

## 后续建议
- {可进一步优化的点}
```

## 3. 变更联动规则（文档一致性）

任何修改完成后，必须检查并同步以下文件：

| 触发变更 | 必须同步更新 |
|---------|------------|
| 新增/删除文件 | `specs/文件索引.md` |
| 修改执行方案 | `plans/plan.md` + 对应 phase 文件 |
| 修改规则 | `specs/规则.md` 版本号 + 所有引用该规则的文件 |
| 修改输出格式 | `output/` 下相关模板 + `docs/` 中格式说明 |
| 新增可复用操作 | memory MCP + `specs/skills/` |
| 调整方案废弃旧文件 | 见 §4.1 废弃处理 |

## 4. 文件检查与写入规则

### 4.1 内容去重与耦合检查
1. **写入前检查**：写入任何文件前，先检查目标文件现有内容，避免重复
2. **内容耦合处理**：发现两个文件有大段相同内容 → 抽取到共享文件，其他文件改为引用
3. **废弃文件处理**（方案调整后旧文件）：
   - 内容仍有价值 → 迁移到新位置或合并到新文件
   - 内容已过时 → 移入 `process/archive/` 并在文件索引中标记 `[DEPRECATED]`
   - **不直接删除**，保留可追溯性

### 4.2 内容归属规则（特定内容写入位置）

| 内容类型 | 写入位置 | 说明 |
|---------|---------|------|
| Agent 执行计划 | `plans/plan.md` | 技术执行步骤和任务编排 |
| 分析讨论结论 | `docs/` | 给人看的分析过程和结论 |
| Agent 执行规范 | `specs/` | 给 agent 看的硬约束 |
| 可复用操作步骤 | `specs/skills/` + memory | Skill 记录 |
| 中间产物/日志 | `process/` | 过程记录，后续可能复用 |
| 正式输出 | `output/` | 最终交付物 |
| 废弃内容归档 | `process/archive/` | 标记 DEPRECATED |
| 新增文件登记 | `specs/文件索引.md` | 必须包含路径、作用、使用方法 |

### 4.3 文件引用规则

**引用价值**：引用不直接省 token，但通过避免重复内容维护一致性，间接减少维护成本。

**遇到引用时是否查看的决策规则**：

| 场景 | 决策 | 理由 |
|------|------|------|
| 引用内容与当前任务直接相关 | ✅ 必须查看 | 影响执行结果 |
| 引用内容是规则/约束类 | ✅ 必须查看 | 可能影响执行方式 |
| 引用内容是背景/上下文，当前任务不涉及修改 | ❌ 跳过 | 节省 token |
| 不确定是否相关 | 🔍 先看文件索引中的描述判断 | 不确定再查看原文 |
